## 一、问题陈述

### 1.1 当前痛点

| 场景 | 当前行为 | 用户体验 |
|---|---|---|
| 跑快手（1024.HK）| ohlcv.db 没港股数据 · 报告标注"数据缺失" | ❌ 报告空 · 没用 |

- ✅ **数据可靠性**（用户强调）· 多源对比 + 校验 + 标注置信度
- ✅ **不破坏现有**（A-J 数据契约 + ohlcv.db 12 只 A 股）
- ✅ **不联网除非必要**（缺数据时才联网）
- ✅ **频率限制**（避免重复抓 + 节省 Tavily 配额）

## 二、架构设计

### 2.1 整体流程

```
[CLI: quick-research / fundamental-research / relation-research / global-research]
   ↓
[数据检测层] 检测 stock/ohlcv/fin_report/tech_indicator 表中缺失字段
   ↓
   ├─ 数据齐全 → 直接跑报告（现状）
   └─ 数据缺失 → 触发 [数据抓取层]
       ↓
       [DataFetcher] 
         ├─ Step 1: 优先级调度（数据源优先级 1→2→3→4）
         ├─ Step 2: 并行抓取（≥ 2 源）
         ├─ Step 3: 多源校验（一致性检查）
         ├─ Step 4: 合理性检查（PE ≥ 0 / 市值 > 0 / 价格偏离 ≤ 10%）
         ├─ Step 5: 落库（INSERT OR REPLACE + 审计字段）
         └─ Step 6: 返回 FetchResult（data + confidence + sources + warnings）
       ↓
[报告生成] 用新数据 + 标注 "数据源 · 抓取时间 · 置信度"
```

### 2.4 多源校验机制

**2 源对比**（强校验）：
```python
def validate_multi_source(price_a: float, price_b: float, src_a: str, src_b: str) -> tuple[bool, float, str]:
    """价格类数据多源校验
    返回: (is_valid, consensus_value, confidence_level)
    """
    diff_pct = abs(price_a - price_b) / max(price_a, price_b) * 100
    if diff_pct <= 1.0:
        return (True, (price_a + price_b) / 2, "high")  # ≤ 1% 偏差 = 高置信
    elif diff_pct <= 5.0:
        return (True, (price_a + price_b) / 2, "medium")  # 1-5% = 中置信
    elif diff_pct <= 10.0:
        return (True, min(price_a, price_b), "low")  # 5-10% = 低置信（取保守值）
    else:
        return (False, None, "failed")  # > 10% = 校验失败，丢弃
```

**合理性检查**：
```python
def validate_sanity(field: str, value: Any) -> tuple[bool, str]:
    """单字段合理性检查"""
    if field == "pe_ttm" and value < 0:
        return (False, "PE 负值 · 通常代表亏损 · 需手动核实")
    if field == "mcap" and value <= 0:
        return (False, "市值 ≤ 0 · 数据异常")
    if field == "price" and (value <= 0 or value > 10000):
        return (False, "价格异常（≤ 0 或 > 10000）")
    if field == "volume" and value < 0:
        return (False, "成交量负值")
    return (True, "ok")
```

### 2.5 频率限制

```python
class FetchRateLimiter:
    """同一股票 30 分钟内不重复抓（避免刷 + 节省 Tavily 配额）"""
    TTL_SECONDS = 1800  # 30 分钟
    _cache: dict[str, datetime] = {}
    
    def can_fetch(self, code: str) -> bool:
        last = self._cache.get(code)
        if last is None or (datetime.now() - last).seconds > self.TTL_SECONDS:
            return True
        return False
    
    def record_fetch(self, code: str) -> None:
        self._cache[code] = datetime.now()
```

## 六、风险与限制

### 6.1 已知风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **数据源不稳定** | 抓取失败 | 4 源并行 + 兜底标注 |
| **Tavily 配额限制** | 频繁抓 → 配额耗尽 | 30 分钟 TTL + 提示升级 |
| **多源不一致** | 报告置信度低 | 偏差 ≤ 1% high / ≤ 5% medium / ≤ 10% low / > 10% failed |
| **港股数据延迟** | 全球收盘后 30 分钟延迟 | 标注"数据时效 · 仅供参考" |
| **schema 变更** | 落库失败 | 增量 ALTER TABLE + 事务回滚 |

### 6.2 用户规则遵守

- ✅ **USER.md L27 早盘纪律** · 抓取数据不影响开盘判断
- ✅ **USER.md L29 翻译层** · 数据原文是英文不翻译（保留）
- ✅ **USER.md L31 推送规则** · 抓取不自动推送
- ✅ **USER.md L15 不主动下单** · 抓取不影响交易决策
- ✅ **永久规则 · 信息时效性** · audit.log 记录 fetched_at，报告标注时间

### 6.3 配额策略

| 数据源 | 用户配额 | 本机制消耗 | 兜底 |
|---|---|---|---|
| 腾讯 | 无限制 | 每次抓取 1 次 | — |
| global-stock-data | 无限制 | 每次抓取 1 次 | — |
| Tavily | **1000 次/月**（剩余配额监控 · L 永久规则）| 30 分钟 TTL · 同股票不重复 | 降级到东财 |
